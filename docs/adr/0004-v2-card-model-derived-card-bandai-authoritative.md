# v2 card model: derived Card over flat Printings, Bandai authoritative

The v2 model keeps the flat **Printing** keyed as in [ADR 0002](0002-printing-key-game-language-bandai-id.md) and adds a **Card** that is derived by grouping **Printings** on Game + **Base Number**, with no table or file level of its own. This links **Languages** and **Variants** at about 4,000 Printings per Language without a second stored entity; a two-level Card + Printing file stays an option only if a card-level fact appears that no Printing carries.

- **One Printing table.** `known_printing` merges into the catalog Printing table. Rows carry a source (Catalog, Custom, last-known); a refresh that drops a Printing sets **No longer in the Catalog** instead of using a second table. An **Owned Copy** still points at a **Printing**, never at a **Card**, and a **Custom Printing** is never merged into a later Catalog Printing.
- **Bandai is authoritative.** The pipeline publishes structured fields from Bandai: **Variant** (so the app stops parsing the `_pN`/`_rN` suffix), the **Rarity** code, and an optional **Product code** next to the **Release Product** text. Where any other source disagrees, Bandai wins.
- **Treatment is a curated overlay.** Manga, foil, stamp and similar tags are added by a hand-curated, reviewed overlay in the private catalog repo, matched to Bandai Printings in the pipeline only. An enrichment source never creates, removes or re-keys a Printing, a mismatch means no tag, and the app never calls a third party. Coverage starts with English booster sets.
- **Refresh and restore ([#59](https://github.com/scwardbulldog/TCG-Reader-Collector/issues/59)).** A refresh replaces Catalog rows from the new file; a dropped row stays, flagged **No longer in the Catalog**, only while an **Owned Copy** uses it, and a returning row clears the flag. Custom rows are untouched. Backups add last-known details for flagged rows only, so a restore never shows a bare ID where the details were known; the Catalog's details win when it has the Printing. A re-ID'd card is never remapped: the old Printing is flagged and the new one is separate. The v2 app migrates the database in place and keeps the Collection tables, and v1 backups still restore because the key is unchanged.
- **Why not third-party data directly.** Research ([#57](https://github.com/scwardbulldog/TCG-Reader-Collector/issues/57)) found no source with both clear terms and structured variant data: labels are free text and inconsistent, matching below **Base Number** is fuzzy outside booster sets, and several terms forbid reuse or are unclear. Bandai's own terms restrict use to personal use, so card data stays in the private catalog repo and published files.

Source: [What is the v2 card model and Printing identity, and what is the card concept called?](https://github.com/scwardbulldog/TCG-Reader-Collector/issues/55).
