# Other sources for per-Printing variant kind and rarity code (issue #57)

All pages and endpoints were read on **2026-11-27** unless a different date is given. Requests were few and polite (custom User-Agent, a handful of calls per host, no bulk crawling). Scope: sources **beyond** Bandai's official list, optcgapi, Limitless and onepiece.app, for English and Japanese One Piece Card Game data. Bandai conventions are taken from `research/printing-scenarios` and `research/catalog-sources`.

## TL;DR

- **No outside source is good enough to publish a reliable per-Printing variant kind in both English and Japanese.** The ones that classify well forbid reuse (Scrydex, Yuyu-tei, foxcard, optcg-api's data). The ones that allow reuse (tcgcsv, dotgg) give only free-text name tags or none at all, and are English-first.
- **Rarity code:** every credible source already agrees with Bandai's codes (`L, C, UC, R, SR, SEC, P, SP CARD, TR`). Bandai's own list remains the cleanest, and the outside sources add nothing there. TCGplayer even drops `SP`.
- **Variant kind** is the real gap. Bandai's rarity cannot tell a manga from an ordinary alt art (`OP05-119`, `_p1`, `_p2` are all `SEC`). Outside sources do split it, but only through free-text labels.
- **Best new find: dotgg.gg** (`api.dotgg.gg/cgfw/getcards?game=onepiece`). It is an open JSON endpoint, free for commercial use with a credit link. It keys rows by Bandai-style IDs (`OP05-119_p2`), gives a rarity code, a language (`en`/`jp`/`jpe`) and the **TCGplayer productId** (`marketIds`) per row. That productId is a bridge from a Bandai Printing ID to tcgcsv's name tags. The bridge is imperfect (243 productIds are shared by two or more EN IDs). It also uses Bandai IDs as keys, so it adds no source-independence.
- **Best structured variant labels:** TCGplayer via tcgcsv.com (EN only). Tags such as `(Alternate Art)`, `(Parallel)`, `(Manga)`, `(SP)`, `(Reprint)` and `(Jolly Roger Foil)` are in the product name. Naming is inconsistent per set, and the terms are a grey area.
- **Japanese** has no reusable structured source. Yuyu-tei and foxcard classify finely (パラレル, スーパーパラレル) but forbid reproduction. Bandai's own JP product pages label super parallels per ID, but only as marketing HTML.
- **Recommendation:** publish Bandai's rarity code as the only dependable code. Treat variant kind as an optional, hand-curated overlay keyed on Base Number plus the Printing, built with tcgcsv/dotgg as an English aid and Bandai product pages and foxcard as manual Japanese cross-checks. Leave it unset when sources disagree.

## 1. tcgcsv.com / TCGplayer (English only)

**Fields and access.** One Piece Card Game is category 68 with 90 groups; `last-updated.txt` showed 2026-11-26T20:05Z. A search of the categories list found no Japanese One Piece category (`Pokemon Japan` exists, One Piece does not). Product records carry `productId`, `name`, `cleanName`, `imageUrl`, `groupId`, `url`, `modifiedOn` and `extendedData` (`Rarity`, `Number`, `Color`, `CardType`, `Cost`, `Power`, …); prices are a separate endpoint. Access is documented static files: `https://tcgcsv.com/tcgplayer/{category}/{group}/products`. The docs ask for one pull per 24 hours, a custom User-Agent, 100 ms between calls and no browser CORS (https://tcgcsv.com/docs, https://tcgcsv.com/faq).

**Separation of variants (spot checks).** There is no dedicated variant field; the kind lives in the name.

- `OP05-119` (all `SEC`): product 527024 plain; 530122 `(Alternate Art)`; 527026 `(Alternate Art) (Manga)`. In PRB-01 it also has `(Alternate Art)`, `(Manga)` and `(Reprint)`. TCGplayer therefore separates the manga, which Bandai's rarity cannot. The tag wording varies (`(Manga)` vs `(Alternate Art) (Manga)`), and it does not map to `_pN`.
- `OP01-001` is `(Parallel)` in the OP01 group; `OP05-100` has base, `(SP)`, `(Alternate Art)`. Naming for the same idea differs by set: OP01/OP07 say `(Parallel)`, OP05 says `(Alternate Art)`.
- `OP06-068` in PRB-01 shows `(Jolly Roger Foil)` and `(Full Art)`. `OP07-091` promo (Bandai `_p1`, rarity R) is product 586024 `Monkey.D.Luffy (091) (Offline Regional 2024 Vol. 3)`, rarity R. The promo's name drops the set prefix of the Number, so matching needs more than the name.
- Name-tag counts over about 2,815 cards in 9 groups: Alternate Art 207, Reprint 200, Pirate Foil 90, Jolly Roger Foil 72, Parallel 71, Full Art 50, SP 35, Manga 23, Textured Foil 22, plus hundreds of event names.
- Rarity codes seen: R, C, PR, UC, SR, L, SEC, TR (TR on only 2-3 products, e.g. `Trafalgar Law (010) (TR)`). There is **no `SP` rarity**; SP is a name tag over the underlying rarity. Event promos use `PR` in some places and the base rarity in others.

**Licence and terms.** tcgcsv FAQ: "How do I get permission to use TCGCSV? You don't. Permission is implicit." It calls copyright a "nebulous grey area"; `robots.txt` allows all; the repo (CptSpaceToaster/tcgcsv) has no licence file. The underlying data is TCGplayer's. TCGplayer's terms (help.tcgplayer.com article 205004918, seen only as a search snippet because the page returned 403; last updated 2023-09-27) say you may not "crawl, scrape or spider" the site without permission, and the API terms (article 360061115874, snippet) restrict collecting content by automation and uses that undermine TCGplayer's business. TCGplayer is no longer granting new API access. The permission tcgcsv offers is the middleman's, not TCGplayer's. Publishing only derived facts (a variant-kind label, a rarity code) is lower risk than publishing names, images or prices, but it is **not** cleared.

**Matching to Bandai Printings.** `extendedData.Number` gives the Base Number (`OP05-119`). It does not give `_pN`. A match is Base Number + group + tag + image/order, which is fuzzy. Event promos have partial or odd Numbers.

## 2. dotgg.gg public API (English and Japanese)

**Fields and access.** `GET https://api.dotgg.gg/cgfw/getcards?game=onepiece&mode=indexed` returns the whole game in one JSON response (5,877 rows). Fields include `id`, `id_normal`, `rarity`, `cardType`, `name`, `Color`, `CardSets`, `set`, `language`, `marketIds` (TCGplayer productId), `cmid`/`cmurl` (Cardmarket) and prices. No key is needed. The docs (https://dotgg.gg/api/) call it "as-is", with no uptime or accuracy guarantee.

**Separation of variants.** There is **no variant field**, but the `id` is Bandai-style, so `_pN`/`_rN` come through (`NNN`: 3,267; `_p1`: 1,117; `_p2`: 520; `_r1`: 448 …). Language counts: `en` 5,501, `jp` 61, `jpe` 315 (`jpe` appears to be Japanese-printed cards sold in English markets; this is inferred, not documented). Rarity codes match Bandai: C 1,983, R 1,158, UC 891, SR 810, L 383, P 332, SEC 154, `SP CARD` 153, TR 13.

Spot checks:
- `OP05-119`: base, `_p1` and `_p2` are `SEC`; `_p7` and `_p8` are `SP CARD`. `marketIds` are `_p1` = 530122 (TCGplayer "(Alternate Art)"), `_p2` = 527026 (TCGplayer "(Alternate Art) (Manga)"), but `_p3` = 527024, which is the **plain** product, and `_p5` repeats 527026. So the bridge is useful but not one-to-one.
- `OP07-091_p1` (rarity R) = 586024, which TCGplayer lists as the Offline Regional 2024 Vol. 3 promo. This is a correct match.
- `OP01-001_p3` is tagged `jp` but carries the EN productId 454512 (same as base), so the JP rows reuse EN ids rather than carrying their own.
- Across EN rows, 243 `marketIds` are shared by two or more different IDs (615 rows), e.g. `ST01-010` and `ST01-010_p2`. Eighteen EN rows have none.
- A direct Bandai comparison for `OP07-109` was not conclusive (my fetch of one Bandai series page showed only the base and `_p1`, while dotgg lists `_p1`–`_p5`, `_r1`); I did not resolve this.

**Licence and terms** (https://dotgg.gg/api/, read 2026-11-27): "You may use the public API free of charge, in commercial and paid products too." The condition is a direct, live link to dotgg.gg on a public page. "Card images, card names and game text belong to their publishers. We share the data as we host it and cannot grant rights to their content." The site may block heavy use. This permits ingesting derived facts, with a credit link, but dotgg cannot grant rights to Bandai's content and gives no accuracy guarantee. The catalog file would need a credit/provenance entry for dotgg if used.

**Matching to Bandai Printings.** Direct on `id` (it uses Bandai IDs verbatim), which is convenient but means dotgg is **not** an independent identity; it inherits Bandai's per-language suffixes and gaps. Its real value is `marketIds` as a link to TCGplayer tags, and `language`.

## 3. Bandai JP product pages (first-party hint)

`https://www.onepiece-cardgame.com/products/boosters/op13/` (read 2026-11-27) is marketing HTML. The image alt text carries IDs and labels: `OP13-118_p2` is "SUPER PARALLEL" (スーパーパラレル) and `OP13-118_p3` is "RED SUPER PARALLEL" (レッドスーパーパラレル); the same holds for `OP13-119_p2/_p3` and `OP13-120_p2/_p3`. There is also an explainer, "スーパーパラレルとは". This is the only place I found a variant kind attached to a Bandai suffix ID by the publisher itself. The layout varies by product, there is no structured data, and I checked only OP-13. The terms are the same Bandai terms as the card list (see `catalog-sources.md`), so this is a manual cross-check, not a feed.

## 4. Discarded sources

- **Scrydex** (https://scrydex.com/docs/onepiece/cards, /pricing, /terms). Best vocabulary: `rarity_code`, `variants[].name` with `foil`, `altArt`, `mangaAltArt`, `redMangaAltArt`; EN examples only. Paid API (Starter $29/mo). Terms forbid reverse engineering/extracting datasets, "Resell, sublicense, redistribute, mirror, or commercially exploit the Services", and use as a "substitute backend, proxy, or wholesale data source for a competing commercial product". That conflicts with publishing a derived catalog file. Its vocabulary may inform our own kind names, nothing more.
- **Yuyu-tei** (https://yuyu-tei.jp/sell/opc/s/op05, https://yuyu-tei.jp/info/rule/). Cleanest Japanese split: for `OP05-119` it lists plain `SEC`, `P-SEC (パラレル)` at about ¥19,800 and `P-SEC (パラレル)(スーパーパラレル)` at about ¥598,000. That is the manga, consistent with TCGplayer's tagging. It uses its own numeric ids and no `_pN`. The rules say images, text and content belong to the shop and unauthorised reproduction is prohibited. Discard.
- **foxcard.jp** (robots: `Allow: /`; privacy policy https://foxcard.jp/privacy-policy). Uses Bandai IDs in URLs (`/onepiece-cardgame/cards/OP13-118_p2`) and lists by kind: `/cards/parallel` (736), `/cards/super-parallel` (48), `/cards/leader-parallel`, `/cards/event-parallel`, `/cards/rarity/sp`. `OP13-118_p2` and `_p3` are both in super-parallel, matching Bandai's product page. Lists nest (`OP17-005_p2` is in both parallel and super-parallel). Provenance of the classification is not documented, and the policy reserves copyright and allows only quotation. Discard; useful as a human cross-check.
- **arjunkai/optcg-api** (README, `classify_variants.py`). Exposes `variant_type`, `print_label`, `stamp`. The classifier is simple: it scrapes Limitless search pages (`is:manga`, `is:serial`) to mark manga and serial cards, and everything else defaults to `_pN` = Alternate Art and `_rN` = Reprint. That is a reminder that a "classification" can be a default rule, not evidence. It mints `_jpN` and `{base}_t{productId}` ids. README: MIT covers code only, no rights to data. Discard.
- **Cardmarket** (`products_singles_18.json`, 13,151 products). Fields `idProduct`, `name`, `idExpansion`, `idMetacard`, `dateAdded`; no rarity, variant or language. `OP05-119` has 20 products with identical names across 10 expansions. `robots.txt` has `Content-Signal: ai-train=no, use=reference`. Discard.
- **apitcg.com**: TCGplayer mirror behind a key (1,000 requests/month free), no Japanese. Subsumed by tcgcsv. Terms not read.
- **punk-records / vegapull-records / optcgjson**: Bandai scrapes; rarity as words (`Special`, `TreasureRare`, `Promo`), no variant kind. Same upstream terms as Bandai.

## Ranked recommendation

1. **Bandai's own list for rarity code** (no outside source improves it). Keep Bandai's `L, C, UC, R, SR, SEC, P, SP CARD, TR`.
2. **Variant kind as a hand-curated overlay, not a scraped field.** Seed it from tcgcsv name tags (English), with dotgg's `marketIds` to attach a tag to a Bandai Printing ID. Confirm by eye against Bandai product pages and foxcard for Japanese. Where the bridge is ambiguous (shared productId, `_p3` → plain product) leave the kind unset.
3. **dotgg** is the only open, low-friction source that spans EN and JP and states a reuse policy. Treat it as a convenience and cross-check, not a source of truth, and credit it if used.
4. **tcgcsv/TCGplayer**: use only for derived labels, keep names, images and prices out of the published file, and accept the grey-area risk knowingly.
5. **Discard** Scrydex, Yuyu-tei, foxcard, optcg-api data and Cardmarket for ingestion.

**If "good enough" means a complete, automatic, reliable per-Printing variant kind: none is good enough.**

**Source-independent identity.** Nothing found justifies one. dotgg and foxcard both reuse Bandai IDs. optcg-api's `_t{productId}` and `_jpN` show how fragile minted ids are. Third-party ids (TCGplayer productId, Cardmarket idProduct) can be stored as optional cross-references, never as identity.
