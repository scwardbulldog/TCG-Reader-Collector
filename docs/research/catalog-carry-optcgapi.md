# optcgapi as a source for per-Printing Variant kind, rarity code and Release Product

Research for [#57](https://github.com/scwardbulldog/TCG-Reader-Collector/issues/57) (blocks #55), optcgapi only. It extends `research/catalog-sources:research/catalog-sources.md` (#2) and `research/printing-scenarios:docs/research/printing-scenarios.md` (#52) and does not redo them. Terms follow [GLOSSARY.md](../../GLOSSARY.md); identity is [ADR 0002](../adr/0002-printing-key-game-language-bandai-id.md).

All optcgapi facts were read live on **2026-11-27** from `https://optcgapi.com` (about 40 GET requests: the docs page, `allSets`, `allDecks`, per-card endpoints, and whole-set endpoints for ten sets/decks; I did not call the `all*Cards` bulk endpoints). "Bandai" below means the private Catalog file `catalog/onepiece-en.json` (generated 2026-11-27, 5,119 Printings), i.e. Bandai's EN list. Only a few IDs are quoted; no card data is reproduced. Counts marked "sample" cover only the sets named, not the whole API.

## Summary

- optcgapi is a hobby Django/MySQL REST API, **English only**, fed by a daily scraper (the owner says it scrapes the web, first the official site; the API covers what is "Active on TCG Player"). It has no licence, terms page or `robots.txt`.
- Its per-card record has **no structured Variant, finish, language or product-code field**. The Variant kind lives only in the free-text `card_name` suffix (`(Alternate Art)`, `(Parallel)`, `(SP)`, `(Manga)`, `(Jolly Roger Foil)`, `(Full Art)`, `(Textured Foil)`, `(Wanted Poster)`, `(Reprint)`, `(TR)`).
- On the **set endpoints** it mirrors Bandai's IDs closely: in `OP-08`, `OP-09`, `OP-11` and `EB-01` every one of 546 optcgapi `card_image_id`s equals the ID of a Bandai Printing in the same product, and vice versa. It fails on `PRB-01`/`PRB-02` and on **promos**.
- Its **rarity is a short code** (`L C UC R SR SEC TR PR`) with **no code for Special (SP)**: Bandai's `Special` Printings carry the base card's rarity (`C`/`R`/`SR`/`SEC`). Bandai's `TreasureRare` is only partly `TR`.
- Its **kind labels are the only source in this research that separates manga, SP, Wanted Poster, Jolly Roger foil, textured foil and full art**, but they are free text from a retail catalogue, inconsistently applied (`Parallel` vs `Alternate Art` for the same concept, label sometimes missing), and `card_image_id` is **not unique** (duplicates inside one endpoint, reused bare IDs in the promo endpoint, a malformed ID).
- Promo Printings use its own `_prN` IDs and are split finer than Bandai (13 optcgapi entries for `P-001` against 7 Bandai Printings); the event is in the name, not a field.
- No terms were found, so republishing is **neither licensed nor refused**; the data is in any case Bandai/TCGplayer-derived.

## 1. What the API publishes

Sources: [optcgapi.com/documentation](https://optcgapi.com/documentation) (the endpoint panes are in an inline `contentDict` script in the page source, read 2026-11-27), [/about/general](https://optcgapi.com/about/general), [/about/updates/](https://optcgapi.com/about/updates/), and live responses.

### Endpoints

| Group | Endpoints (docs) | Notes (live, 2026-11-27) |
|---|---|---|
| Sets | `/api/allSets/`, `/api/allSetCards/`, `/api/sets/{set_id}/`, `/api/sets/card/{card_id}/`, `/api/sets/filtered/`, `/api/sets/card/twoweeks/` | `allSets` returns 23 products. `set_id` looks like `OP-01`, `EB-01`, `PRB-01`, and the merged `OP14-EB04`, `OP15-EB04`. |
| Starter decks | `/api/allDecks/`, `/api/allSTCards/`, `/api/decks/{st_id}/`, `/api/decks/card/{card_id}/`, `/api/decks/filtered/`, `/api/decks/card/twoweeks/` | `allDecks` returns 35 decks (`ST-01` to `ST-36`, no `ST-29`). Deck records still use the card schema below, with `set_id` like `ST-21`. |
| Promos | `/api/allPromoCards/`, `/api/promos/filtered/`, `/api/promos/card/{card_id}/`, `/api/promos/card/twoweeks/` | The docs text shows `allPromos` as the example URL, but the endpoint list says `allPromoCards`. Docs say `promos/card/twoweeks/` is "Still being worked on!". |
| Don!! | `/api/allDonCards/`, `/api/don/filtered/` | Different schema (`don_id`, `optcg_don_name`, `card_image_id` like `don_1`). |

- Filters on `*/filtered/`: `card_name, color, set_id, set_name, rarity, card_type, card_cost, card_power, attribute, card_image_id`.
- GET only, no auth. Response headers: `Access-Control-Allow-Origin: *`, `Allow: OPTIONS, GET`; no rate-limit or cache headers seen. The docs ask users not to make "an insane amount of API calls each day"; the About page says "the API will have some limits on how much data can be pulled each day" (no numbers).
- A card must be looked up per group: `/api/sets/card/ST12-003/` returned `[]` (it is under `decks`, and again under `promos`). The same bare ID can exist in two groups with different meaning (section 2).
- A custom `User-Agent` containing "bot" got a 1.3 KB non-document response from `/documentation` in my first attempt; the default curl agent worked. I did not investigate further.

### Fields per card (set, deck and promo records share one schema)

From live `/api/sets/OP-09/` records and the docs examples:

| Field | Values seen | Meaning |
|---|---|---|
| `card_name` | free text | Name **plus** disambiguation and kind suffixes: `Roronoa Zoro (001) (Parallel)`, `Monkey.D.Luffy (119) (Alternate Art) (Manga)`, `Gum-Gum Lightning (Premium Card Collection -Best Selection Vol. 4-)` (promo, docs example). |
| `card_set_id` | `OP01-001`, `P-001` | The Base Number (no suffix). |
| `card_image_id` | `OP01-001`, `OP01-001_p1`, `_rN`, promo `_prN`; `null` for many promos | Looks like Bandai's ID on set endpoints. Also the image file name. |
| `card_image` | `https://optcgapi.com/media/static/Card_Images/OP01-001_p1.jpg`, or with a random suffix (`OP13-031_RqMf0Sh.jpg`); `null` for most promos | Re-hosted JPG (HEAD returned 200 `image/jpeg`). Not derivable from the ID: use the field. |
| `rarity` | `L C UC R SR SEC TR PR` (`DON!!` on the Don!! endpoint) | Short code. |
| `set_id`, `set_name` | sets and decks `OP-09`, "Emperors in the New World"; promos `OP07` or `P`, "One Piece Promotion Cards" | Product reference. |
| `card_color`, `card_type`, `card_cost`, `card_power`, `life`, `counter_amount`, `attribute`, `sub_types`, `card_text` | numbers as strings; absent values are `"NULL"` or `null` | Game data. |
| `market_price`, `inventory_price` | USD, TCGplayer-style | Prices; `Day{N}_*` columns only on `twoweeks`. |
| `date_scraped` | mostly ISO (`2026-11-27`); 55 of 1,037 sampled rows hold `10/14/2025`-style text | Per-row scrape date, two formats. |

There is **no** `language`, `variant`, `finish`, `is_parallel`, `product_code` or `release_date` field. The `set_id` shape differs by endpoint (`OP-01` for sets and decks, `OP07` or `P` for promos).

### ID scheme, languages, update cadence, images

- **IDs.** `<base>` (normal), `<base>_pN` (parallel-like), `<base>_rN` (reprint) on set and deck endpoints; `<base>_prN` on the promo endpoint, numbered in scrape order (`P-001_pr1` to `_pr12`), with the oldest entry holding the bare ID (`P-001`, `OP07-091`). A malformed ID occurs (`OP09-078-r1` in `PRB-02`, hyphen instead of `_`).
- **Language.** English only. The About page says the API "covers all current sets and structure decks that are Active on TCG Player for the English Release of the game"; the home page snippet (2026-11-23) says the data "is based off the english release". No JP data, no language field.
- **Coverage gaps against Bandai EN (2026-11-27).** `allSets`/`allDecks` have no `OP-18`, `ST-29`, `SD-01`, `GC-01` or `GC-2026`, all of which are product codes in Bandai's EN list. The About page is stale: it still says "OP01 - OP12 ... ST01 - ST28" while the live list reaches `OP-17`/`EB-05`.
- **Cadence.** About page: a scraper pipeline "automatically updated every day". Live evidence: `date_scraped` is the day of my request on most rows but older on others (`2025-07-21`, `2026-02-09`), so it is a per-row last-scrape date, not a freshness guarantee. The update log has five entries, the last on 2026-03-15. New sets and promos are added by hand ("I will try to be as active as possible").
- **Images.** Re-hosted JPGs (not Bandai's PNG URLs). Most promo entries have `card_image_id` and `card_image` null; the About page says there are "over 900 unique Promo cards on TCG Player" and many images are missing.

## 2. Does it separate parallel / manga / SP / foil / reprint / promo?

Method: for `OP-08`, `OP-09`, `OP-11`, `OP-13`, `PRB-01` and `EB-01` (1,037 rows) I matched `card_image_id` to a Bandai EN Printing `id` and compared; `PRB-02` and `ST-21` (520 rows, `OP-13` re-read) were used for extra checks. Bandai's conventions are those of the printing-scenarios note: the suffix only says "another Printing" (`_pN`, `_rN`); kind is only visible through rarity (`Special`, `TreasureRare`) and the picture.

### Kind labels

| Kind | How optcgapi expresses it | Reliability observed |
|---|---|---|
| Normal | No suffix in the ID, no label (the name often has `(001)` or `(OP06-068)` for disambiguation) | Good on set endpoints. |
| Parallel / Alternate Art | `_pN` plus `(Parallel)` or `(Alternate Art)` | The words mean the same thing and are mixed: in `OP-08` all 25 plain parallels say `Parallel`; in `OP-13` 28 say `Alternate Art` and 7 say `Parallel`. 10 of 391 `_p` rows in the six-set sample have no kind label. |
| SP | `_pN` plus `(SP)` | In `OP-08/09/11/13`, all 35 Bandai `Special` Printings carry `(SP)` or `(Wanted Poster)`. But `(SP)` also appears on a Bandai `TreasureRare` (`OP07-109_p2`). |
| Wanted Poster | `(Wanted Poster)`: 7 rows in those four sets, plus one `(SP) (Wanted Poster)` | Bandai calls these `Special`; the distinction exists only in optcgapi. |
| Manga | `(Manga)` on `_p` (7 rows, 2 more combined with Alternate Art/Parallel) and on `_r` IDs (8 rows) | Bandai's rarity for these is `SecretRare`, not `Special`, so Bandai alone gives no hint. optcgapi labels `OP05-119_p2` (OP-05) and `OP05-119_r2` (PRB-01) as Manga, so a Bandai `_rN` is **not only a same-art reprint**. |
| Treasure Rare | `(TR)` and `rarity: TR` | Of the 4 Bandai `TreasureRare` Printings in `OP-08/09/11/13`, 2 are `TR`, 1 is `(SP)` and 1 has no label; the rarity of the latter two is `SR`. `ST18-004_p1` (Bandai `TreasureRare`) is `SR` and unlabelled. |
| Foil / full art | `(Jolly Roger Foil)` (72 rows), `(Textured Foil)` (22), `(Full Art)` (49) | Mostly the PRB-01 style products (Bandai has no equivalent text). |
| Reprint | `_rN` plus `(Reprint)` | Of 105 `_r` rows in the six-set sample 46 say `(Reprint)`, 8 say `(Manga)` and 51 have no kind label (`OP06-068_r1` is just "Vinsmoke Reiju"). 4 `_p` rows say `(Reprint)`. |
| Promo | Another endpoint (`/api/promos/…`), `set_name` "One Piece Promotion Cards", rarity mostly `PR`, event in the name `(Offline Regional 2024 Vol. 3) [Finalist]`, own `_prN` IDs | Rarity is `PR` for some regular-card promos and the original for others (`OP07-091` promos are `R`, `ST12-003` Regionals is `PR`, `ST12-003` Illustration Box is `SR`); Bandai keeps the original rarity except on `P-` numbers. |

So optcgapi is the only source in this research that can say manga, SP, Wanted Poster and foil per Printing, but only as text parsed from a display name written for a marketplace.

### Rarity coding

optcgapi code to Bandai rarity, on ID-matched rows in the six-set sample (`OP-08/09/11/13`, `PRB-01`, `EB-01`; 1,037 rows, of which 1,030 matched):

| optcgapi | Bandai rarity of the same ID (rows) |
|---|---|
| `L` | `Leader` 56 |
| `C` | `Common` 280, `Special` 4 |
| `UC` | `Uncommon` 200 |
| `R` | `Rare` 251, `Special` 5 |
| `SR` | `SuperRare` 148, `Special` 14, `TreasureRare` 2 |
| `SEC` | `SecretRare` 44, `Special` 12 |
| `TR` | `TreasureRare` 2 |
| `PR` | `Promo` 12 |

Reading: the code vocabulary is the common retail one (`C UC R SR SEC L`); `Special` has **no code** and falls back to the base card's rarity; `TR` covers only some Treasure Rares. So optcgapi's rarity is a lossy re-coding of Bandai's, and cannot tell an SP Printing from the normal one. `SP` exists only in the name label.

### Where it disagrees with Bandai or invents Printings

1. **Duplicate `card_image_id` inside one product.** `PRB-01` returns 317 rows with 309 distinct IDs: eight IDs are shared by two Printings of different kind (`OP01-033_p5`: "(Alternate Art)" and "(Full Art)"; `OP03-094_p3`: "Jolly Roger Foil" and "Textured Foil"). Bandai lists these as separate IDs (`OP01-033_p4`, `_p5`). `OP-13` has `OP13-084` twice (normal and "(Parallel)" without `_p1`).
2. **IDs Bandai does not have**: 7 of 317 in `PRB-01` (`OP01-078_r3`, `OP03-108_p7`, …) and 4 of 156 in `PRB-02` (`OP04-083_r3`, `OP06-007_p6`, the malformed `OP09-078-r1`, …). The "(Reprint)" rows probably stand for Bandai's `_r1` Printings under other numbers, but that is inference. 18 Bandai `PRB-01` Printings (`OP01-041_p3`, `EB01-006_r1`, …) have no optcgapi counterpart by ID.
3. **Promos are a separate ID space.** `OP07-091` has three Bandai EN Printings (`OP07-091`, `OP07-091_p1`, `OP07-091@569901_p1`; the Finalist/Participation split of #50); optcgapi's set endpoint has the normal card and its promo endpoint six entries (`OP07-091`, `_pr1` to `_pr5`, Online and Offline Regional, Winner and Finalist), of which two correspond to Bandai's products. The bare ID `OP07-091` means the base card in the set endpoint and an Online Regional Winner in the promo endpoint.
4. **Finer than Bandai.** `P-001`: optcgapi 13 entries (Winner / Finalist / Participant × Online / Offline, Super Pre-Release, Store Championship Trophy, Gift Collection 2023, Promotion Pack 2022, Alternate Art, …) against 7 Bandai Printings (`P-001`, `_p1` to `_p6`); Bandai's `_p3` "Premium Card Collection -25th Edition-" has no optcgapi entry. Whether the extras are physically distinct cards is outside the primary sources, so I do not call them wrong.
5. **Same Bandai concept, different tag.** Bandai `TreasureRare` `OP07-109_p2` is optcgapi `(SP)` with rarity `SR`. Bandai `Special` `OP05-119_p6` is "(Wanted Poster)" with rarity `SEC`.
6. **Missing products** (`OP-18`, `ST-29`, `GC-01`, `GC-2026`, `SD-01`), see section 1.
7. **Never-listed Printings are covered** (#52 scenarios 9 and 11): `ST12-003_pr1` (Illustration Box Vol.4) and `PRB02-012` "(Welcome Pack 2026 Vol.1)", which reuses the bare ID that the set endpoint gives the normal Nami. The JP milk stamp (scenario 10) is absent: `OP06-068` has no promo entry and its set entry has `_p2` "(Jolly Roger Foil)", `_p3` "(Full Art)" and an unlabelled `_r1`.

### Does the ID hold identity? No

`card_image_id` is not unique (point 1), is reused with different meaning across endpoints (`PRB02-012`, `ST12-003`, `OP07-091`, `P-001`) and can be malformed. `_prN` numbers are scraper-assigned and shift as entries are added. This supports ADR 0002: another source's ID is never the Printing's identity.

## 3. Matching optcgapi Printings to Bandai Printings

`card_set_id` is the Base Number and agrees with the Bandai `baseNumber` (1 exception in the 520 rows checked: the malformed `OP09-078-r1`). **Base Number is a usable join key** for "this record is about that card", but not for picking the Printing:

| Match attempt | Works | Fails |
|---|---|---|
| Base Number | Always, as a many-to-many group (Bandai 3 to 9 Printings per card in the examples; optcgapi 1 to 9 across the set, deck and promo endpoints). | Never selects one Printing. |
| Base Number + product (`set_id` to the `[OP-09]` code in Bandai's `releaseProduct`) | Clean for booster sets: all 546 IDs in `OP-08/09/11/EB-01` pair one-to-one with a Bandai ID in the same product. | `PRB-01`/`PRB-02` reprint boosters (duplicate and invented IDs); promo products (Bandai's text is the "Information Obtained" string, optcgapi's is inside `card_name`); Bandai splits `OP07-091` by pack, optcgapi by event. |
| optcgapi `card_image_id` = Bandai `id` | Exact in the clean sets. | The collisions and invented suffixes above; a promo `_prN` never equals a Bandai `_pN`. Using this equality as the rule would make their IDs identity. |
| Name | No: optcgapi adds `(091)`, `(OP06-068)` and kind suffixes (as #52 found). | Everything. |
| Image | Not examined here. | Not checked. |

What a mismatch should do: the Bandai Printing stays as is, without a kind; the optcgapi entry stays unmatched and is never turned into a Printing. A merge keyed on (Base Number, product, ID) is reliable only for booster sets; promos would need a product-name table.

## 4. Licence and terms

- **No terms of service, privacy page, FAQ, licence file or `robots.txt`**: `/robots.txt`, `/terms`, `/faq`, `/privacy`, `/about` and `/sitemap.xml` all returned 404 (2026-11-27). The site's pages are Home, About (General Info, Updates), Documentation and card pages. A GitHub search finds only a third-party SDK (`laiambryant/optcgapi-go-sdk`, MIT), which licenses the SDK, not the data.
- **What the owner says**: the API is "consumption only", "doesn't require authentication, and it is open for anyone to use", run on a paid VPS, "please try not to do an insane amount of API calls each day" ([documentation](https://optcgapi.com/documentation), 2026-11-27); "the API will have some limits on how much data can be pulled each day" ([about](https://optcgapi.com/about/general)).
- **Footer on every page**: "One Piece and the One Piece Trading Card Game data are trademarks of Eiichiro Oda, Bandai, Shonen Jump, and Viz Media. Please support the official release …".
- **Provenance**: the owner describes the data as scraped from the web (initially from the official site) and "Active on TCG Player"; names and the `market_price`/`inventory_price` fields follow TCGplayer's convention (inference). Names, text and art are Bandai's. No ownership or licence is claimed for any of it.
- **Consequence for us**: permission to *call* the API is stated; permission to *copy and republish* its content in our own catalogue file is **neither granted nor refused**. Do not publish its text, prices or IDs without the owner's written agreement (the About page gives a Discord handle, `domothebot`), and Bandai's own terms apply to the underlying data (see #2: use beyond personal use needs Bandai's permission). A derived fact such as "this Bandai Printing is a manga card" is a fact about the card, not a copy of optcgapi's record, but a catalogue built by bulk-copying its labels is copying its data. This note is not legal advice.

## What the catalog can take from optcgapi (and what it cannot)

1. **As a tagging overlay, never as a Printing source**: a variant-kind hint (`alternate-art`, `parallel`, `sp`, `manga`, `wanted-poster`, `treasure-rare`, `foil`, `full-art`, `reprint`) matched on Base Number + product + ID **only where the match is one-to-one** (booster sets), left blank otherwise. Even then it is a free-text parse of a retail name; it would need a pinned mapping table and tests, and it is a hint that Bandai's data cannot contradict.
2. **Not a rarity source.** Bandai's rarity text is complete (it includes `Special` and `Promo`); optcgapi's is a lossy re-coding. A rarity *code* should be derived from Bandai's text.
3. **Not a Release Product source** for promos (generic set name) or the PRB boosters (broken IDs).
4. **Never** its IDs, prices or names. EN only: JP Printings get no hint.
5. Licence: no terms, so any ingestion into a published file needs the owner's agreement first.

## Open points

- Counts are from sample sets, not the whole API; a full pass with the bulk endpoints (three requests, but a bulk download) was avoided on purpose.
- Primary sources do not say whether TCGplayer or the official site is the origin of the `(Alternate Art)` style labels; the About page mentions both.
- The rule for `(Parallel)` versus `(Alternate Art)` is undocumented.
- Bandai's rule for `_rN` versus `_pN` is still undocumented. optcgapi labelling manga `_rN` Printings in `PRB-01` suggests `_rN` means "reprinted in a later product" regardless of art; worth checking against Bandai's list images.
- Whether optcgapi's Winner / Finalist / Online-Regional promo entries are physical cards absent from Bandai's list was not verified.
- The owner was not contacted; the licence position is an absence of terms, not a refusal.
