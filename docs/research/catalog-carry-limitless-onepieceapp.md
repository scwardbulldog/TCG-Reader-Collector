# What Limitless and onepiece.app can carry per Printing

Research for [#57](https://github.com/scwardbulldog/TCG-Reader-Collector/issues/57) (parent #51; feeds #55). Scope: Limitless (`onepiece.limitlesstcg.com`, `play.limitlesstcg.com` and its API docs) and onepiece.app only. Extends `research/catalog-sources:research/catalog-sources.md` and `research/printing-scenarios:docs/research/printing-scenarios.md`; vocabulary follows `GLOSSARY.md`.

All facts were read on **2026-11-27**, with a handful of requests (about 30 in total, 1 to 2 seconds apart, honest User-Agent). Nothing was bulk-scraped. Pages change daily; this is a snapshot.

## TL;DR

- **Neither source is a catalog feed.** Limitless publishes no card API at all (its API is tournament-only, confirmed) and onepiece.app publishes a key-gated **price** API. Both are HTML-first, EN-first, and built around the *market product*, not Bandai's Printing.
- **Limitless card pages do carry usable per-print data**, but thinly: one row per print with a product (set) name, a free-form variant label (`aa`, `manga`, `wanted`, `jr`, `fa`, or blank), prices, and an image whose file name has a `_pN` suffix **that is Limitless's own index, not Bandai's**. Rarity exists only for the base print and only as a name ("Secret Rare"); variant prints show **no rarity**.
- **onepiece.app carries the richest variant vocabulary** (`MANGA`, `SP`, `ALT ART`, "SP Gold", "Reprint", "Wanted Poster", "Textured Foil", and a `PROMO` pseudo-set) and a rarity **code** (`SEC`), but it is a mirror of **TCGplayer products**: identity is the TCGplayer `productId`, names and variant text are TCGplayer's, and its "SEC" is the base card's rarity, not Bandai's `SP CARD`.
- **Both separate parallel / manga / SP better than Bandai's suffix does**, but neither agrees with Bandai's Printing count for the one card I compared in depth (`OP05-119`: Bandai EN 9 listings, Limitless 8, onepiece.app 10).
- **Both can be matched to a Bandai Base Number** (`OP01-001` appears literally in URLs/fields), but only at the Base Number level. Matching to an individual Printing needs product + variant heuristics and fails on realistic cases.
- **Licence:** no source offers a data licence. Limitless has no card-data terms (its ToS covers the tournament platform; card text/images are Bandai's, credited as such). onepiece.app's API terms allow commercial use **with visible credit** but forbid re-selling the raw feed, require an approved key, and its own `/legal` page contradicts the API page ("offers no API"). Neither is safe to ingest into a **published catalog file**.
- **Recommendation:** use neither as a source of record; at most use onepiece.app/Limitless as an optional, advisory, non-identity cross-check for a `variantKind` hint. See "What the catalog can publish".

## 1. What each source exposes

### Limitless (`onepiece.limitlesstcg.com`)

**Documented API (`play.limitlesstcg.com/api`)** — tournament data only. The developer docs list four pages: Introduction, Tournaments, Games, Webhooks (`https://docs.limitlesstcg.com/developer.html`, `/developer/tournaments.html`, `/developer/games.html`). The intro says the API provides "placings, decklists and matches" and "tournament data"; keys "are not meant for private use" and go only to "public-facing projects" (`developer.html`). `GET /games` returns game, format and platform ids, `GET /games/{id}/decks` returns deck-categorisation rules. **There is no cards or printings endpoint.** I called `GET /tournaments?game=OP&limit=1` and `/tournaments/{id}/standings` once: OP decklist entries are `{"count", "name", "set", "number"}` (for example set `OP09`, number `042`), i.e. **no print/variant field**, so even the tournament data cannot say which Printing was played.

**Card pages (HTML only).** No JSON, no JSON-LD on the page I checked, no bulk export, `sitemap.xml` returned 404. The structure:

| Item | Where / what | Example (read 2026-11-27) |
|---|---|---|
| Card URL | `/cards/<BaseNumber>`, `/cards/en/..`, `/cards/jp/..`; print selected by `?v=N` | `https://onepiece.limitlesstcg.com/cards/OP01-001`, `?v=1` |
| Per-card fields | name, Base Number (`.card-text-id`), category, color, cost/power/life, attribute, effect text, type line, "Block" mark, legality | OP01-001: Roronoa Zoro, Leader, Red, 5 Life, 5000 Power, Block 1 |
| Set / product | Set slug page (`/cards/op01-romance-dawn`); each print row names its **product in free text** | "Romance Dawn (OP01)" for the card; print rows "Premium Card Collection -25th Edition-", "Regional Participation Pack 2024 Vol.3", "Misc. Promos" |
| Variant | A short label next to the product in the "Print" table; blank when none | `aa`, `manga`, `wanted`, `jr`, `fa`, or blank |
| Variant index | `?v=N`, N is Limitless's own order for that card | `OP05-119?v=1..7` |
| Rarity | **Not on the card page.** Visible in the set list view (`?display=list`) and searchable (`/cards?q=rarity:SEC` returned "43 cards found where rarity is Secret Rare"). Shown as a **name**, not a code (`Common`, `Uncommon`, `Rare`, `Super Rare`, `Secret Rare`, `Leader` in OP01). **Variant rows have an empty rarity cell.** | In the OP01 list: 121 base rows have rarity; the 33 parallel rows (e.g. `OP01-013?v=1`) have none |
| Images | `https://limitlesstcg.nyc3.cdn.digitaloceanspaces.com/one-piece/<SET>/<BaseNumber>[_pN]_<EN|JP>.webp` | `OP01-001_EN.webp`, `OP01-001_p1_EN.webp`, `OP05-119_p7_JP.webp` |
| Languages | EN and JP toggle (`/cards/en/`, `/cards/jp/`); `lang` filter `all/en/jp` | Same card has `OP05-119_JP.webp` |
| Prices | TCGplayer USD and Cardmarket EUR per print, with affiliate links containing the TCGplayer product id and Cardmarket slug | Roronoa Zoro OP01-001 `$1.96` |
| Update cadence | Header shows "Latest Updates: EB05 • OP18"; no changelog or timestamp on card data | Fast for new sets |

**Notes on the ID scheme.** The only stable, public key is the **Base Number** (URL). The print identity is `?v=N` plus the image file's `_pN`; these coincide with each other but **not with Bandai's `_pN`** (see section 2). Product has no code, only text, and the set page slug is a name slug.

**`play.limitlesstcg.com`** has no card data (the site is the tournament platform; `/robots.txt` there returns the HTML 404 page). `limitlesstcg.com/bandai` is a short "Bandai Card Lists" index of cards supported in decklist submission, not a data source.

### onepiece.app ("OnePiece Terminal")

A **market-price terminal** (booster box EV, graded values, PSA pop), not a card database; its own description is "One Piece TCG market data and prices" and "Fan-made, not affiliated with Bandai or Shueisha" (JSON-LD on `/card/594325-...`, `/legal`). English only: "Live market prices for every English One Piece card" (`/api-docs`); "6,400+ cards" (JSON-LD).

| Item | Where / what | Example (read 2026-11-27) |
|---|---|---|
| Card URL | `/card/<TCGplayerProductId>-<slug>`; set page `/set/<SetCode>`. **Not** `/cards/OP01-001` (404, as noted in the earlier note) and not by Base Number. | `/card/594325-op05-119-monkey-d-luffy-op05-119-reprint` |
| Identity | TCGplayer product id (`sku` and `productId` in the page JSON; image at `/img/594325`) | `594325` |
| Per-card fields | Base Number and **rarity code** ("OP05-119 · SEC"), color, cost, power, effect text, set code + set name, price, graded prices | PRB01 Reprint Luffy: `OP05-119 · SEC` |
| Variant | Parsed from the TCGplayer product name; shown as a badge and in names | Badges `MANGA`, `SP`, `ALT ART`; names "(Alternate Art) (Manga)", "(SP) (Gold)", "(Wanted Poster)", "(Textured Foil)", "(Reprint)", "(English Version 2nd Anniversary Set)"; the SP page adds "also called SP Silver" |
| Set / product | Set code + name in page header; a **`PROMO` pseudo-set** holds tournament/event promos ("1,100+ promos priced daily") with the Base Number kept | `PROMO · OP02-053 Crocodile (Online Regional 2023) [Finalist]` |
| "All printings" | Each card page lists every sibling product for the Base Number | OP05-119: 10 printings |
| Languages | English only | n/a |
| Images | TCGplayer CDN images, proxied | `tcgplayer-cdn.tcgplayer.com/product/594325_200w.jpg` |
| Update cadence | "synced nightly at 22:00 UTC" (`/methodology`); home page "Data as of 2026-11-26" | nightly |
| Coverage gaps | Home page: "25 OP01-OP16 + EB/PRB specials" tracked booster boxes (EB05/OP18 pages exist) | n/a |

**API.** `https://onepiece.app/api-docs` documents `GET /api/v1/cards` (params `set`, `search`, `limit` max 200, `offset`; sorted by market price) returning `id, name, number, set, rarity, variant, market_usd, url`, and `GET /api/v1/sets` (box prices and EV). Access "is granted by hand" with an approved key, 5,000 requests per day and 60 per minute per IP. I did **not** sign up or call it. So the API's existence (and `rarity` and `variant` fields) is documented; **the exact value vocabulary of `variant` is not documented** and was not observed.

## 2. Do they separate parallel / manga / SP / foil / reprint / promo?

Comparison card: EN `OP05-119` (the same card used by the earlier notes). Bandai EN list, queried once (`https://en.onepiece-cardgame.com/cardlist/?freewords=OP05-119`): 9 listings.

| Bandai EN ID | Rarity text | Bandai product (Information Obtained) |
|---|---|---|
| `OP05-119` | SEC | OP05 Awakening of the New Era |
| `_p1`, `_p2` | SEC, SEC | OP05 |
| `_p4`, `_r1`, `_r2` | SEC (all three) | PRB-01 ONE PIECE CARD THE BEST |
| `_p6` | SP CARD | OP-09 Emperors in the New World |
| `_p7`, `_p8` | SP CARD, SP CARD | OP-11 A Fist of Divine Speed |

| Source | Rows for `OP05-119` | What it says |
|---|---|---|
| Limitless (EN page) | base + 7: OP05 `aa`, OP05 `manga`, OP09 `wanted`, PRB-01 `aa`, OP11 (blank), OP11 (blank), "English Version 2nd Anniversary Set" `aa` | Image names `OP05-119_p1..p7`; **v=7 image is `_p7_JP.webp`** |
| onepiece.app | 10 TCGplayer products: OP05 base, OP05 Alt Art, OP05 Alt Art + Manga, PRB01 Alt Art, PRB01 Manga, PRB01 Reprint, OP09 Wanted Poster, OP11 SP, OP11 SP Gold, "English Version 2nd Anniversary Set" (promo) | `OP05-119 · SEC · SP` on the SP page; `... · SEC · MANGA` on the manga page |

Findings:

1. **Variant kind.** Bandai's suffix says only "another Printing" and its rarity text separates only `SP CARD` (and `TreasureRare` and so on; not manga). onepiece.app gives explicit `MANGA`/`SP`/`ALT ART` and a name hint for gold/foil/wanted/reprint; Limitless gives `aa`/`manga`/`wanted`/`jr`/`fa` but **leaves the two OP11 SP prints with a blank label** and shows `wanted` where onepiece.app/Bandai call it a Wanted-poster SP. Neither carries an explicit, closed vocabulary; both are scraped/derived labels. Neither exposes "foil" as a separate flag (onepiece.app shows a price type "Foil · TCGplayer market" on every card including the non-foil base, which is a price category, not a card property).
2. **Rarity.** onepiece.app's code (`SEC`) is the **base card's rarity applied to all its variants**: the SP page says `SEC · SP`, whereas Bandai lists the same Printing as `SP CARD`. Limitless: base print only, long name, blank on variants. So rarity of a *Printing* is not reliably recoverable from either; Bandai's list stays the source for it.
3. **Reprint.** onepiece.app labels the PRB-01 reprint explicitly; Limitless has no reprint label (it relies on product name and lists one PRB-01 row where Bandai has three: `_p4`, `_r1`, `_r2`, and onepiece.app three: Alt Art, Manga, Reprint). Limitless therefore **merges or omits Printings**, as the printing-scenarios note already saw for scenario 8 and for `OP06-068`.
4. **Promo.** Limitless puts promos in the same print table (`P-001` has 7 rows: "Misc. Promos", "Prize Cards" `fa`/`aa`, "Gift Collection 2023", and so on). onepiece.app moves tournament promos to a `PROMO` pseudo-set while keeping the regular Base Number (`OP02-053`, `OP02-098`), which agrees with Bandai's "promo of a regular Base Number, rarity kept" convention but **not** with Bandai's product (Bandai lists such cards inside generic promo packs; onepiece.app uses TCGplayer's event name in the card name).
5. **Where they disagree with Bandai (concrete):**
   - Count: 9 (Bandai) vs 8 (Limitless) vs 10 (onepiece.app) for `OP05-119`.
   - Suffix: Limitless `_p3` is the OP09 Wanted print, Bandai's is `_p6`; Limitless `_p4` happens to be the PRB-01 `aa` and matches Bandai `_p4`. The suffix agrees by coincidence, not by rule.
   - Language: Limitless's JP page for `OP05-119` shows the **same 7 English-named product rows** and an image `_p7_JP.webp` for the "English Version 2nd Anniversary Set". Bandai's EN list has no such product, Bandai's JP list does (`_p8`, per printing-scenarios scenario 12). Limitless's JP/EN toggle therefore shares one print table across Languages, which cannot reproduce per-Language suffix numbering (scenario 16).
   - JP `OP06-068`: Limitless JP shows `jr` and `fa` under "One Piece Card The Best" and no stamp (matches the earlier note: stamp absent).
   - Names: onepiece.app uses TCGplayer disambiguation names such as "Monkey.D.Luffy (119) (SP) (Gold)" and "(OP05-119)"; Bandai's name carries none (already noted for optcgapi).

## 3. Matching to Bandai Printings

- **By Base Number: yes, for both.** Limitless puts the Base Number in the URL and `.card-text-id` (`OP01-001`, `P-001`), onepiece.app has it in the page header (`OP05-119 · SEC`), the card slug (`op05-119-...`) and the API field `number`. Both include `P-` and promos of regular numbers (`P-001`; `OP02-053`). This is enough to answer "which Base Numbers does this source mention?", with no dependence on their own ids.
- **By Printing: no, not reliably.** The join would be Base Number + product text + variant hint, i.e. fuzzy. Product names are free text and differ (Limitless "Awakening of the New Era" vs Bandai "-AWAKENING OF THE NEW ERA- [OP05]" vs onepiece.app "OP05 Awakening of the New Era"). Counts differ (above). Bandai has a Printing with no counterpart in either source (`OP05-119_r2` has no distinct row in Limitless), and the sources have Printings Bandai's EN list lacks (the 2nd Anniversary Set). A mismatch must therefore degrade to "unknown", never to a new identity.
- **Not by their ids.** Limitless `?v=N`/`_pN` is a per-card ordinal that is not Bandai's and is shared across Languages. onepiece.app `productId` is TCGplayer's, EN-only, and TCGplayer re-lists products. Neither may become a Printing key (consistent with ADR 0002).
- **Not by image.** Both serve re-hosted Bandai/TCGplayer images (Limitless on its own CDN, onepiece.app via TCGplayer CDN and its own `/img/`), so they match by id/URL nowhere; pixel matching is out of scope here.

## 5. What the catalog can publish (from these two sources only)

| Field | Limitless | onepiece.app | Verdict |
|---|---|---|---|
| Printing key | `?v=N` per card, shared across Languages | TCGplayer `productId`, EN only | Not usable as identity |
| Base Number | Yes | Yes | Usable as a join hint |
| Variant kind (parallel/manga/SP/foil/reprint/promo) | Free label, incomplete (blank for OP11 SP) | Best vocabulary (`MANGA`/`SP`/`ALT ART`, name hints), derived from TCGplayer product names | Advisory only; not a closed vocabulary, EN only, no foil flag |
| Rarity (code) | Name only, base print only | Code, but the base card's rarity (`SEC` on an SP Printing) | **Not Printing rarity**; Bandai stays the source |
| Release Product | Free text per print row; set page slug | Set code + name; `PROMO` pseudo-set | Free text only; no code from Limitless; onepiece.app set code is a set, not a Bandai product (and promo products collapse into one) |
| Languages | EN/JP toggle, shared print table | EN | Per-Language Printings not representable from either |
| Images | Own CDN of Bandai artwork | TCGplayer CDN | Do not republish |
| Prices | USD/EUR | USD | Out of scope for the catalog |
| Cadence | Quick (new sets show in header) | Nightly 22:00 UTC | Fine for a cross-check |

## Recommendation

1. **Do not use Limitless or onepiece.app as a source of record** for Variant kind, rarity or Release Product. Their structure follows market products (TCGplayer, Cardmarket), they disagree with Bandai on Printing counts and suffixes, they merge or invent Printings, and neither grants a licence for republication.
2. **If a variant kind must be a structured field**, derive it where the catalog is built from Bandai's own signals (`SP CARD` rarity text, `_rN`, product class) and treat third-party labels as an optional, unstable hint. A third-party hint would at most be a non-identity enrichment keyed by **Base Number + Release Product text**, with a mismatch resulting in "no hint".
3. **Rarity** stays Bandai's code, per Printing, from Bandai's list; do not take it from either source.
4. **Release Product** stays free text from Bandai ("Information Obtained") unless a code can be derived from Bandai's product pages; neither source supplies a Bandai product code.
5. If a hint source is wanted later, **onepiece.app is the more informative one** (explicit `MANGA`/`SP`/`ALT ART`) but needs an approved key and credit and has EN-only data; **Limitless is the only one with JP pages** but those reuse the EN print table. Either use needs its terms re-checked and, for onepiece.app, a written answer on republication.

- Whether Limitless's label vocabulary is complete: seen `aa`, `manga`, `wanted`, `jr`, `fa`, blank across `OP01-001`, `OP05-119`, `OP06-068`, `P-001`, `ST12-003`; others (for example SP, TR) were not seen.
- Only one card (`OP05-119`) was compared against Bandai in depth; counts elsewhere are not measured. The earlier note's observations on `OP06-068`, `ST12-003`, `OP07-091` were re-read in Limitless only: `OP07-091` has one extra row "Regional Participation Pack 2024 Vol.3" (the Finalist and Participation merge), and `ST12-003` has "Misc. Promos" and "Regional Participation Pack 2026 Vol.1" rows, both consistent with the earlier note.
- Limitless's EN versus JP print table: JP page for `OP05-119` showed English product names and the same 7 variants; I did not check whether other JP-only products (e.g. Japanese promo packs) appear.
- Limitless `/cards/syntax` (search syntax docs) returned HTTP 500; the full search grammar was not read.
- No legal review; no contact with either site. Terms may change.
