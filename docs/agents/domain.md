# Domain docs

This repo uses a single context. Before exploring, read the root `GLOSSARY.md` and any decisions in `docs/adr/` relevant to the task. If either is absent, continue without it. `/domain-modeling` creates these files when terms or decisions are settled.

Use glossary terms in issues, proposals, hypotheses, and tests. If a term is missing, check existing project language before proposing it and note genuine gaps for `/domain-modeling`. Explicitly flag any proposal that conflicts with an ADR and explain why the decision may need reopening.
